## 1. Response-envelope parsing

The model must return one UTF-8 JSON object and no Markdown fences or surrounding prose. The canonical JSON Schema is `34_OpenVEF_Response_Schema_v1.0.json` (Draft 2020-12); schema version `1.0` is independent of the planning-pack version. Reject invalid UTF-8, BOM, leading/trailing prose, Markdown fences, trailing non-whitespace, truncated JSON, duplicate object keys, unknown/missing fields, wrong constants, wrong filenames and wrong field types. Do not strip code fences, coerce values, recover from malformed JSON or silently normalize source code. Provider max-token truncation is `OUTPUT_TRUNCATED` at `PARSE_SCHEMA` and is reported separately.

Validate each `assumptions[].clause_id` against the exact `clause_ids` array and `clause_id_regex` in the frozen manifest. Valid values are an exact member of that array or the reserved literal `UNSPECIFIED`. Contract text in fixed B5/B7/B8 paragraphs is not citable; only clause IDs in design-specific author-visible payloads may be cited. The F18 equality check requires the set of regex-matching IDs in the visible payload bytes to equal the manifest `clause_ids` set exactly. `UNSPECIFIED` is permitted only for behavior not specified in the received packet, and the text must identify the missing behavior. Unknown IDs are rejected. The mask is never used to derive a clause list.

**JSON Pointer selection rule.** Run the pinned Draft 2020-12 validator and collect every schema validation error. Convert each error's `absolute_path` to an RFC 6901 token sequence: escape `~` as `~0` and `/` as `~1`; the project display form for the root pointer is `/`. For `required` and `additionalProperties`, report the parent instance pointer, not a missing/extra child name. Sort errors by (1) instance token sequence, lexicographically by Unicode code point with a shorter equal prefix first; (2) validator keyword rank `additionalProperties`, `required`, `const`, `type`, `minLength`, `maxItems`, then all other keywords alphabetically; (3) schema token sequence under the same token ordering; (4) canonical JSON of `validator_value` (UTF-8, sorted object keys, separators `,` and `:`). Report the instance pointer of the first sorted error. Duplicate JSON object keys and envelope-level syntax/encoding errors use `/`.

## 2. Language and permitted imports

- Language: Python 3.11; exact patch version, container digest and parser/library versions remain TO FREEZE.
- Permitted import roots are exactly: `__future__`, `collections`, `copy`, `functools`, `itertools`, `json`, `math`, `operator`, `random`, `re`, `statistics` and `typing`. The modules `abc`, `dataclasses` and `enum` are intentionally not allowed because the selected strict AST policy prohibits helper classes and decorators.
- An `ast.Import` node may contain exactly one imported name. The exact per-node priority is: `MULTIPLE_NAMES` (more than one alias); then a disallowed root as `IMPORT_NOT_ALLOWED|module=<root>`; then dotted root as `IMPORT_FORM_REJECT|reason=SUBMODULE_IMPORT`; then alias as `IMPORT_FORM_REJECT|reason=IMPORT_ALIAS`; otherwise accept the exact root. Thus `import math, json` is `MULTIPLE_NAMES`, `import os.path` is `IMPORT_NOT_ALLOWED|module=os`, `import collections.abc` is `SUBMODULE_IMPORT`, and `import math as m` is `IMPORT_ALIAS`.
- An `ast.ImportFrom` node uses this total priority: relative level (`RELATIVE_IMPORT`); star alias (`STAR_IMPORT`); multiple names (`MULTIPLE_NAMES`); then the `__future__` rule (unsupported future feature → `FUTURE_FEATURE`; `annotations` with alias → `IMPORT_ALIAS`; exact single unaliased annotations import is accepted); disallowed root (`IMPORT_NOT_ALLOWED`); every remaining non-future from-import (`FROM_IMPORT_FORBIDDEN`). The only accepted form is exactly `from __future__ import annotations` without alias. Multi-name precedence applies before the future-feature check, so `from __future__ import annotations, division` and `from __future__ import annotations, annotations` are `MULTIPLE_NAMES`. `from collections import abc` and `from collections.abc import Iterable` are `FROM_IMPORT_FORBIDDEN`; `from os import path` and `from os import path as p` are `IMPORT_NOT_ALLOWED|module=os`; `from __future__ import annotations, annotations` is `MULTIPLE_NAMES`.
- AST `Name` nodes whose `id` is `__import__`, `eval`, `exec`, `compile` or `open` are rejected, regardless of call context. A `builtins` attribute whose attribute is one of those names is also rejected. `builtins` itself is not an allowed import root. The built-in name `compile` is prohibited; `re.compile` is explicitly allowed.
- `import random` is permitted only for constructing a local `random.Random(seed)`. Any direct attribute access on the module name `random` other than `random.Random` is rejected, including module-global PRNG calls and `random.SystemRandom`. Static detection may be bypassed by aliasing (`r = random; r.random()`) or `getattr`; disclose this limitation. Such bypasses are not statically claimed as detected and are caught only if they cause a paired next-input divergence at runtime. `from random import ...` is not permitted by the general from-import rule. The artifact must not call OS-entropy APIs.
- Every Python identifier lexeme must be ASCII. After successful `ast.parse` and before import-node classification, scan `tokenize.NAME` and identifier-relevant `tokenize.ERRORTOKEN` tokens in source order. For `ERRORTOKEN`, define `START(c)` as `c.isidentifier()` and `CONTINUE(c)` as `("A" + c).isidentifier()` under pinned Python 3.11. For each non-ASCII error-token code point, reconstruct the maximal same-line contiguous run containing it by extending left and right across `CONTINUE` characters; it is an identifier lexeme only if its first character satisfies `START`. Reject the complete lexeme at its first character. Unicode in STRING and COMMENT tokens is permitted. `column` is the one-based UTF-8 byte column at the start of the complete identifier lexeme, not the source-character column. The non-ASCII check wins over import form/root classification on the same statement. Never echo the offending lexeme.
- No third-party package, dynamic import, filesystem access, network access, environment access, wall-clock access, process/thread creation, subprocess call or package installation is permitted. The schema `dependencies` array must be empty.
- The exact allow-list, import form, built-in-name rule, `re.compile` exception and local-random rule are stated to the model in B8. The module/class/decorator rules are stated in B5 and B7. F18 compares these model-visible fixed texts byte-for-byte with the normative copies below.

## 3. AST and runtime entry-point validation

For file-local stages, process each source file in this order: strict UTF-8 decode with BOM rejection; empty/whitespace-only rejection; `ast.parse`; module-level AST policy; import/prohibited-name policy; compilation; restricted-runtime import; runtime `inspect.signature` and factory-return checks. No source is imported before every static check passes. File-local syntax, tokenizer, import and module-body stages process `driver.py` before `checker.py`; within a file, source nodes use ascending `(lineno, col_offset, end_lineno, end_col_offset)`. `AST_SIGNATURE` is the explicit exception: first validate required symbols in the fixed sequence, then select any remaining structural violation globally across both files using the category sort key below.

**Shared AST rules and stage ownership:** Stage `IMPORT_POLICY` checks module-body statements other than `ast.FunctionDef`, `ast.AsyncFunctionDef` and `ast.ClassDef`; all function/class definition nodes are deferred to `AST_SIGNATURE`. At module scope, classify only import statements, an optional module docstring, and assignments/annotated assignments whose values are recursively literal-only. `ast.FunctionDef`, `ast.AsyncFunctionDef` and `ast.ClassDef` nodes (including decorator lists and bodies) are deferred entirely to `AST_SIGNATURE`; `IMPORT_POLICY` never rejects or classifies a function/class definition. A non-literal assignment emits `NON_LITERAL_CONSTANT`; module-level control flow (`if`, `for`, `while`, `with`, `try`, `match` and async control flow) emits `MODULE_CONTROL_FLOW`; other executable statements/calls/expressions emit `MODULE_EXECUTABLE`. At `AST_SIGNATURE`, every `ast.AsyncFunctionDef` at any lexical depth, including an async function nested inside a synchronous helper, is checked exactly once under the precedence below. In addition, explicitly inspect `ast.GeneratorExp`, `ast.ListComp`, `ast.SetComp` and `ast.DictComp` nodes: any one with at least one associated `ast.comprehension` with `is_async == 1`, or with any `ast.Await` node anywhere in its AST subtree, is an asynchronous comprehension and must be rejected at category rank 7 as `ASYNC_COMPREHENSION`; it is not represented by `ast.AsyncFunctionDef`. Python treats a generator expression containing `await` as asynchronous even when every `is_async` flag is 0. The subtree test also catches await in filters, later `for` clauses, nested lambdas and list/set/dict comprehensions. This explicitly catches a valid async generator expression such as `(item async for item in stream)` inside a synchronous function. An async binding of a required symbol (`create_driver`, `Driver.step`, `check_trace`) emits `WRONG_ENTRY_POINT_KIND` in the required-symbol pass. An async direct `Driver` method other than `step` emits `FORBIDDEN_METHOD` (rank 3). A decorated async definition emits `DECORATOR_REJECT` (rank 5). Every other async definition emits `ENTRY_POINT_REJECT` with reason `ASYNC_DEFINITION` (rank 6); the `ASYNC_DEFINITION` reason belongs to `ENTRY_POINT_REJECT`, not `MODULE_STATEMENT_REJECT`. Any decorator emits `DECORATOR_REJECT` with error class `ENTRY_POINT_REJECT`; any class in `checker.py`, any class other than the single module-level `Driver` in `driver.py`, or any nested class emits the specified `ENTRY_POINT_REJECT`. All function, class and method decorators are forbidden. Async functions, async generators and async comprehensions are forbidden; async-generator functions defined with `async def` are covered by the `AsyncFunctionDef` rule, while async generator expressions are covered by the `ASYNC_COMPREHENSION` rank-7 rule. A standalone `await` expression, `async for` statement or `async with` statement anywhere outside an `ast.AsyncFunctionDef` (including synchronous function bodies and headers, lambdas and class bodies), when not contained in a comprehension expression caught by rank 7, passes `ast.parse` and `AST_SIGNATURE` but is rejected by Python `compile()` as `COMPILE_ERROR|file=<FILE>|line=<LINE>` at `COMPILE_DRIVER` or `COMPILE_CHECKER`. Any `ast.Await` node inside a comprehension expression is handled by rank 7 before compilation. Literal-only expressions are `ast.Constant` values of type string, bytes, integer, float, complex, boolean or `None`, and recursively nested tuple/list/set/dict literals containing only those values; unary plus/minus applied to a numeric literal is permitted. Names, calls, comprehensions, f-strings, attribute access, binary operations and other expressions are not literal-only. Module-level executable statements, control flow, calls, expressions other than a docstring, `with`, `try`, loops, comprehensions, non-literal assignments and other side effects are rejected. The checker and driver may define synchronous undecorated helper functions at any lexical depth not otherwise prohibited by the class/method rules; the parser does not impose a separate module-scope-only restriction on helper functions. Helper functions do not replace the required entry points. The checker may define no classes. The driver may define exactly one `Driver` class; `Driver` has exactly one direct method `step`, no `__init__`, no other direct method, no helper/nested class, no metaclass and no base other than implicit object or explicit `object`.

**ASCII identifier scanner and location rule:** process files in the fixed order `driver.py`, then `checker.py`. Within each file, after strict UTF-8 decoding and successful `ast.parse`, scan `tokenize.NAME` and `tokenize.ERRORTOKEN` tokens in source-position order before classifying any import node, prohibited name or module-body statement in that same file. For a `NAME` token, reject it if any code point is above U+007F. For an `ERRORTOKEN`, inspect non-ASCII code points in source order. Under pinned Python 3.11 define `START(c)` as `c.isidentifier()` and `CONTINUE(c)` as `("A" + c).isidentifier()`. For each such code point, reconstruct the maximal same-line contiguous run containing it by extending left and right across `CONTINUE` characters; the run is an identifier lexeme only when its first character satisfies `START`. Reject the complete lexeme at its first character. This avoids allowing a valid non-ASCII identifier to escape merely because CPython's tokenizer emitted its character as `ERRORTOKEN`. STRING and COMMENT tokens are not scanned, so Unicode in strings, bytes and comments remains permitted. The diagnostic column is the one-based UTF-8 byte position at the start of the entire identifier lexeme, calculated from the UTF-8 byte length of the source-line prefix; it is not the source-character column. A non-ASCII identifier therefore wins over an import-root/form violation on the same statement. After the file's identifier scan passes, continue with that file's import, prohibited-name and module-body checks; then process the next file.

**AST_SIGNATURE assignment and multi-defect precedence:** first validate required symbols in this fixed sequence: `driver.py:create_driver`, `driver.py:Driver`, `driver.py:Driver.step`, then `checker.py:check_trace`. For each required function/method, count all same-name binding definitions at the required scope before inspecting parameters: zero bindings → `MISSING_ENTRY_POINT`; more than one binding of any AST kind → `EXTRA_ENTRY_POINT`; exactly one binding with the wrong AST kind → `WRONG_ENTRY_POINT_KIND`; exactly one binding of the required kind proceeds to parameter checks in the order names, kinds, then defaults/variadic/keyword-only shape. For `Driver`, count top-level bindings named `Driver`: zero → `MISSING_ENTRY_POINT`; more than one → `EXTRA_ENTRY_POINT`; exactly one non-`ClassDef` binding → `DRIVER_CLASS_FORM`; exactly one `ClassDef` proceeds. For `Driver.step`, count direct class-body bindings named `step`: zero → `MISSING_ENTRY_POINT`; more than one → `EXTRA_ENTRY_POINT`; exactly one non-`FunctionDef` binding (including `AsyncFunctionDef`) → `WRONG_ENTRY_POINT_KIND`; exactly one synchronous `FunctionDef` proceeds. Only after every required symbol passes, inspect remaining structure globally across both files. Assign category ranks: (1) any nested class at any lexical depth → `NESTED_CLASS_FORBIDDEN`; (2) any other top-level class in `driver.py` or any class in `checker.py` → `CLASS_FORBIDDEN`; (3) `Driver.__init__` or any other direct `Driver` method besides `step` → `FORBIDDEN_METHOD`; (4) invalid `Driver` base/metaclass → `DRIVER_CLASS_FORM`; (5) any decorator on any function, class or method → `DECORATOR_REJECT` (error class `ENTRY_POINT_REJECT`); (6) any `ast.AsyncFunctionDef` at any lexical depth → `ASYNC_DEFINITION` (error class `ENTRY_POINT_REJECT`); (7) any `ast.GeneratorExp`, `ast.ListComp`, `ast.SetComp` or `ast.DictComp` with at least one associated `ast.comprehension.is_async == 1`, or with any `ast.Await` node anywhere in its AST subtree → `ASYNC_COMPREHENSION` (error class `ENTRY_POINT_REJECT`). A generator expression containing `await` is asynchronous even when all `is_async` flags are 0. A generator expression such as `(item async for item in stream)` is not an `AsyncFunctionDef`, so it requires this explicit category. Use the expression node's own source position for the global key. For an async-comprehension expression, use the expression node's own source position. Define `symbol` by AST ancestry: collect every ancestor `ast.FunctionDef`, `ast.AsyncFunctionDef` and `ast.ClassDef` of which the expression is a descendant, outermost first, and join their names with `.`. This includes expressions in decorators, arguments, defaults, annotations, bases and keywords; exclude lambda names and the expression itself. A `<module>` symbol is unreachable because module-body expressions are rejected at `IMPORT_POLICY` before `AST_SIGNATURE`. Select the first violation using exactly `(category, file_order, lineno, col_offset, end_lineno, end_col_offset)`, where category is the numeric rank above and `file_order` is `0` for `driver.py`, `1` for `checker.py`. Do not run the category pass separately per file: every rank 1–6 violation in either file outranks every rank 7 async-comprehension violation in either file. Within a category, choose the first file by file_order, then the earliest source location. A nested class is checked before top-level class inventory, so `helper.Nested` cannot be reported as `CLASS_FORBIDDEN`. `symbol` is a bare top-level name (`create_driver`, `Driver`, `check_trace`), `Driver.<method>` for Driver methods, dot-joined lexical enclosing names for nested definitions (for example `helper.Nested` or `helper.nested_async`), or dot-joined lexical enclosing definition names for an async-comprehension expression. For an async function definition, include its own name after all lexical enclosing names. M01 demonstrates the forbidden-method category; M02 and M39 demonstrate class categories; M49 demonstrates required-symbol-before-category precedence; M51 and M52 test category precedence within one file and globally across both files; M59 tests an async definition nested inside a synchronous helper; M60 and M61 test async bindings of the required factory and step symbols; M65 and M66 test `async for` generator expressions in driver.py and checker.py; M67–M69 test async check_trace, an extra async Driver method and a decorated async helper; M70 tests a generator expression containing `await`. This global priority is normative.

## 4. Driver call and vector validation

The harness calls `create_driver(seed)` exactly once. It does **not** seed global `random`; the artifact must use a local `random.Random(seed)` instance. The first `step` call occurs after reset release with `cycle_index=0` and the output snapshot sampled after the reset-release active edge. Each later call uses the next integer cycle index and the immediately preceding post-edge public-output snapshot.

A return value is either the exact string `COMPLETE` or a dictionary. For a dictionary, the parser/harness verifies before driving: (a) its key set equals the frozen top-level input-port set exactly; (b) each value is a string; (c) the value length equals the port width; (d) every character is `0` or `1` (X/Z are prohibited on driven inputs); and (e) the full vector satisfies the design-specific legal-input predicate from the author-visible reset/legal-input specification. **OWNER-DECIDED OD-2** (owner decision D-027; v1.3.6 does not state how the predicate is represented): the owners adopt Python 3.11 as its representation. The predicate is frozen as one Python 3.11 function of two dictionaries, `(vector, sampled)`: the driver vector, and the outputs sampled in the same row, each mapping a port name to its bit string. The function is pure: its result depends only on its two arguments, and it has no other effect. It returns the exact Boolean `True` for a legal vector and `False` otherwise. Any other outcome, including an exception, is an evaluator failure and is never an artifact verdict. The predicate is evaluator material, not artifact code: the evaluator executes it, outside every artifact process. It is hash-gated: the SHA-256 of its UTF-8 source is recorded when it is frozen, and the evaluator executes it only after checking that the source has that hash; a mismatch is an evaluator failure. Within check (a), missing keys are reported before extra keys. Checks (a) to (e) run in that order and the first failure is reported. A fixture that exercises check (e) supplies the input properties `driver_return` (the vector), `input_port_widths` (each input port name mapped to its width), `sampled_outputs` (the outputs sampled in the same row) and `legal_input_predicate` (an object with `language` = `python3.11`, `function`, the function's name, `source`, its Python source, and `source_sha256`, the lowercase hexadecimal SHA-256 of `source` in UTF-8, which is the frozen hash of OD-2). Missing keys, extra keys, wrong width, non-string values, illegal symbols and illegal protocol combinations are distinct reason codes. Any invalid vector is not driven.

## 5. Checker contract and metadata

`check_trace(trace, metadata)` runs in a separate process over an immutable serialized trace. `metadata` contains exactly:
- `design_id`: string;
- `spec_version_sha256`: 64-character lowercase hexadecimal string;
- `trace_schema_version`: string;
- `cycle_cap`: positive integer;
- `reset_release_cycle`: non-negative integer;
- `trace_integrity_status`: literal `VALID`.

Metadata excludes driver seed, stimulus list, mutant identity, null/mutant label, observation mask, reference model/API, expected-output values and evaluator-only identifiers.

The return value must be a dictionary with exactly two top-level keys: `verdict` and `diagnostics`. `verdict` must be exactly `PASS` or `FAIL`. `diagnostics` must be a list (an empty list is valid). A well-formed diagnostic item has exactly `code` (string), `message` (string), `cycle` (integer or null) and `clause_id` (string or null). A malformed diagnostic item is logged as `DIAGNOSTIC_FORMAT_WARNING` and discarded; it does not change the verdict or create a checker error. A checker return error is classified in this exact order: (1) a non-dictionary value is `CHECKER_RETURN_INVALID|reason=NON_DICTIONARY`; (2) if the dictionary omits `diagnostics`, use `CHECKER_RETURN_INVALID|reason=MISSING_DIAGNOSTICS`; (3) if its key set is not exactly `{"verdict", "diagnostics"}`, use `CHECKER_RETURN_INVALID|reason=TOP_LEVEL_KEYS`; (4) if `verdict` is not exactly `PASS` or `FAIL`, use `CHECKER_RETURN_INVALID|reason=INVALID_VERDICT`; (5) if `diagnostics` is not a list, use `CHECKER_RETURN_INVALID|reason=DIAGNOSTICS_NOT_LIST`. A malformed individual diagnostic item is handled only as `DIAGNOSTIC_FORMAT_WARNING` and discarded. A process crash is `CHECKER_RUNTIME_ERROR|class=<EXCEPTION_CLASS>`; a wall-clock watchdog is `CHECKER_TIMEOUT|phase=null_check`. A valid `FAIL` verdict on the null trace is a repair trigger.

## 6. Import sandbox and deterministic execution

Enforce the same import allow-list statically and at runtime. The runtime sandbox denies network, filesystem access beyond the designated temporary output directory, environment variables, wall-clock reads, subprocess and simulator access. It must allow the interpreter to initialize the standard-library `random` module under the pinned runtime; artifact code remains prohibited from calling OS-entropy APIs or module-global random functions. F18 must test `import random` plus construction/use of `random.Random(seed)` inside the sandbox before F16. Pin Python patch version, container image digest, JSON Schema validator and parser libraries before F16. Do not use NumPy. The harness uses an explicit `random.Random(seed)` for its own reference-driver stream; it does not provide global random seeding to generated artifacts.
