OpenVEF v0.9 Audit
Nov 22, 2026 · @Conductors
1. Verdict: FAIL for the LLM-call gate
The v0.9 pack is a substantial and mostly faithful response to the v0.8 audit.
• Assembly reproduces exactly. Every hash and byte length in the sidecar matched my own recomputation, and ORG-A and ORG-B differ only in block order.
• The model-visible fixed text matches the parser contract byte for byte.
• The checker return contract is now consistent across B7, file 30 and Protocol §10.
• C9–C17 are essentially done, and the owner and authorization status is honest.
The gate still fails on your definition, because contradictions, missing rules and untestable requirements remain. The most serious one is substantive, not cosmetic:
• The model is still not told the parser's most restrictive AST rules. File 30 rejects any Driver class with an __init__ or any method other than step, any helper class, any decorator (including @dataclass), and any non-literal module-level statement. None of this appears in the prompt. An LLM writing def __init__(self, seed) (the most natural Python) would be rejected for a rule it never saw, which is the N3 defect in a new place.
The remaining blockers are document-level:
• the repair-stage precedence orders the RTL-vs-null control before the driver run that produces it;
• several failure classes are still unmapped;
• exact diagnostic strings and the JSON-Pointer selection rule are undefined;
• file 31 uses a different placeholder syntax from the templates;
• the fixture catalog contradicts file 30 about whether R01–R13 are mandatory.
All are fixable by edits. None needs a redesign. No LLM call is permitted.
What I did. I re-implemented file 31's extraction and rendering in a short Python check, and ran the schema with jsonschema 4.26 against hand-written objects. I made no LLM calls, built no project code, and accessed no source PDFs.
